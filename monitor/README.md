# Thunderbird Enterprise Policy Upstream Monitor

This monitor watches Mozilla’s enterprise policies for changes, which may need to
be ported to Thunderbird. It runs daily via a GitHub Action and creates a GitHub
issue for each Thunderbird version with relevant upstream changes.

> [!NOTE]
> The monitor currently lives in the `monitor/` folder of the
> [policy-templates](https://github.com/thunderbird/policy-templates) repository
> and will be moved into its own repository.

## 📋 What is monitored

For each Thunderbird version (ESR, Release and Daily), the monitor compares the
current upstream state against the last known state and reports:

- **Schema changes** in Mozilla’s [`policies-schema.json`](https://searchfox.org/mozilla-central/source/browser/components/enterprisepolicies/schemas/policies-schema.json)
  of the matching Firefox version:
  - new policies, which are not yet supported by Thunderbird
  - removed policies, which are supported by Thunderbird
  - policies with changed properties, which are supported by Thunderbird
- **Documentation changes** in Mozilla’s [`policy-templates`](https://github.com/mozilla/policy-templates)
  repository (the release matching the Firefox version) for policies supported
  by Thunderbird.

Which policies Thunderbird supports is determined from Thunderbird’s own
`policies-schema.json`.

## 📁 Project Structure

```
├── check_upstream.js      # The monitor script.
├── modules/               # Modules used by the monitor script.
└── upstream/              # The last known upstream state (autogenerated).
```

## 🔄 How it works

1. The last known state is read from `upstream/` of the repository’s `master`
   branch (not from the local checkout).
2. The current upstream state is downloaded and compared against it. Versions
   without a known state (e.g. a new ESR) start at the first build of that
   version.
3. The updated state is written to the local `upstream/` folder and the findings
   are passed to the workflow (`GITHUB_OUTPUT`).
4. The workflow commits the updated `upstream/` folder and creates one issue per
   Thunderbird version with findings.

As long as the updated `upstream/` folder is not pushed, a new run reports the
same findings again.

Downloaded files are cached in `persistent_schema_cache.json`. The workflow keeps
this cache between runs, and falls back to a copy attached to a GitHub release.

## 🛠️ Setup & Usage

Requires Node.js **22+**.

```bash
cd monitor
npm install
node check_upstream.js
```

## 🚚 Moving to its own repository

- Update `MONITOR_REPO_URL`, `MONITOR_REPO_BRANCH` and `MONITOR_REPO_DIR` in
  `modules/constants.mjs`.
- Move `.github/workflows/check.yml` of the parent repository and remove the
  `monitor/` prefixes and `working-directory` entries.
- Attach `persistent_schema_cache.json` to a release of the new repository and
  update the fallback URL in the workflow.
